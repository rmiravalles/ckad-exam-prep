### What we practiced

- Create Pods imperatively using `kubectl run`
- Verify Pod creation with `kubectl get pods`
- Delete Pods imperatively using `kubectl delete pod <pod-name>`
- Generate Pod YAML using `kubectl run --dry-run=client -o yaml > pod.yaml`
- Use the generated Pod YAML to create a Pod with `kubectl apply -f pod.yaml`
- Explore Pod scheduling with `kubectl get pods -o wide`
- Describe Pod details with `kubectl describe pod <pod-name>`
- Retrieve Pods using labels with `kubectl get pods -l <label-selector>`
- Display all the labels of Pods with `kubectl get pods --show-labels`

## F-01: Pod command and arguments

- **Attempt:** `kubectl run echo-once -n ckad --image=busybox:1.36 --command -- /bin/sh -c "echo 'CKAD-ready'; sleep 3600"`
- **Review:** Correct. `--command --` passes `/bin/sh -c` and the shell expression to the container; `sleep 3600` keeps the Pod running. The `ckad` namespace is valid if it exists.
- **Verification:** `kubectl get pod echo-once -n ckad` should show `Running`; `kubectl logs echo-once -n ckad` should contain `CKAD-ready`.
- **Pattern locked in:** With `sh -c`, keep the full shell expression together as one argument.
